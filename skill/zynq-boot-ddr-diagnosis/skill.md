# Zynq 启动与 DDR 分层定位

形式：排错流程

## 适用场景

FSBL 停滞、DDR 初始化失败、JTAG 可运行而自主启动异常。

## 本队题目之外的应用场景

可用于其他 Zynq-7000 核心板、采集终端和机器人控制板的启动排错。

迁移方法：替换 DDR 完整型号、容量与位宽、PS 初始化配置、启动介质和串口日志；沿用按启动阶段定位、OCM 隔离和字节通道统计的步骤。

可复用的输出：最早失败阶段、对照实验及错误地址/字节分布。

## 使用方法

保存完整启动日志和存储器完整后缀；按 BootROM、FSBL、U-Boot、Linux 定位最早失败阶段。用 OCM 驻留程序隔离 DDR，再进行有限区域的地址/数据模式测试。对照器件密度、位宽、频率、CL/CWL和初始化寄存器，每次只改变一个条件。

输出按[实验记录模板](../templates/experiment_record.md)填写输入、步骤、结果与复用条件。

## 协作提示词

> 请按[串口日志、DDR型号、初始化表]定位最早失败阶段，设计 OCM 与 DDR 单变量对照，给出预期值、错误字节与恢复步骤。

方括号由使用者替换为目标项目资料。

## 已验证效果

项目中旧板最低字节错误与新板有限区域零错误形成对照；QSPI/eMMC 启动有独立冷启动记录。

## 经验来源

曾将 OCM/禁用 DDR 的配置作为 Linux 启动基础，导致排查阶段混淆；仅依据软件 MMC 宏也容易误判拨码。

## 失效条件与处理

DDR 完整型号、板卡版本和初始化来源必须对应。有限地址窗口的结果适用于该窗口；启动存储写入前保留可恢复副本。
