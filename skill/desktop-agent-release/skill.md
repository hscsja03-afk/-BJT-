# 上位机与板端代理一致发行

形式：排错流程、发行模板

## 适用场景

Windows GUI、板端 Python 代理、位流和校准数据的打包与部署。

## 使用方法

固定双端 Python 版本，分别列出源码、桌面包、代理、bit/HWH、校准表和启动入口。生成哈希清单，在独立目录打包；部署后读取实际文件哈希并核对入口。按连接、初始化、服务重启和冷启动分别记录结果。界面线程采用消息边界，冻结状态拒绝迟到帧。

输出按[实验记录模板](../templates/experiment_record.md)填写输入、步骤、结果与复用条件。

## 协作提示词

> 请对照[源码、发行目录、代理、自启服务、数据哈希]检查实际入口和版本组合，列出发布与恢复步骤，按实际执行项记录验证结果。

方括号由使用者替换为目标项目资料。

## 已验证效果

项目已采用包/代理/数据读回校验和明确的启动入口；取消、迟到帧、路径定位和初始化顺序有对应离线回归。

## 经验来源

曾出现源码修复但代理包仍旧、数据依赖启动目录、停止后的迟到帧刷新界面等问题。

## 失效条件与处理

版本和路径需从目标工程取得。程序、代理、位流及数据作为一组回滚；界面预览、程序自检、服务重启和冷启动各有自己的验收条件。
